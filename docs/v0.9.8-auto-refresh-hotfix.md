# Volcengine automatic refresh hotfix

The v0.9.8 API worker successfully reads Volcengine usage, but its scheduled path was configured differently from the v0.6.2 lifecycle:

- Codex and DeepSeek used a native hidden-WebView `location.reload()`.
- Volcengine was marked `reload_page = false` and depended on invoking a JavaScript sync hook inside the hidden worker.

This hotfix restores the native reload path for Volcengine. The scheduler stores the refresh metadata in same-origin session storage and reloads the lightweight worker page. On startup/pageshow, the worker replays the three read-only Volcengine APIs and emits the new payload to the main dashboard.

The enterprise usage UI remains unloaded during routine background refresh, and there is still no DOM or ECharts fallback.

# v0.9.8 — 火山方舟会话接口 Worker

v0.9.8 将火山方舟采集从企业版页面 DOM / ECharts 读取，改为网页登录态下的控制台内部只读接口。

## 目标

- 不要求隐藏 WebView 长期停留在 Agent Plan 企业版用量页面。
- 不读取 DOM、React Fiber 或 ECharts。
- 不保留 DOM / ECharts 数据兜底。
- 后台窗口生命周期向 v0.6.2 的 Codex / DeepSeek 模式看齐：窗口只作为持久登录会话容器，刷新时使用 reload 驱动一次完整采集。
- 不要求用户填写 API Key、AccessKey 或 SecretKey。

## 生命周期

1. 首次启动或登录态失效时，火山窗口进入 Agent Plan 企业版页面。
2. 初始化脚本只捕获以下三个只读 XHR 的请求模板：
   - `GetAgentPlanSeatAFPUsage`
   - `ListAgentPlanUsageDetailObjects`
   - `GetAgentPlanSeatUsageDetails`
3. 模板只保存在该 WebView 的 `sessionStorage` 中，包含接口地址、请求体以及必要的 `X-Csrf-Token` / `x-web-id` 请求头；Cookie 始终由 WebView 管理。
4. 三个接口均读取成功后，窗口切换到同源轻量页：
   - `https://console.volcengine.com/robots.txt#token-on-kindle-api-worker`
5. 后续定时刷新和“立即刷新”只使该 Worker reload。reload 后主动调用三个接口并发送规范化数据，不再加载企业版用量界面。
6. 如果接口返回缺少 `Result`、HTTP 失败或模板失效，Worker 清除模板并回到企业版页面，等待用户重新登录或重新建立会话。

## 数据

AFP 来自 `GetAgentPlanSeatAFPUsage`：

- `AFPFiveHour`
- `AFPWeekly`
- `AFPMonthly`
- `Quota`
- `Used`
- `SubscribeTime`
- `ResetTime`

模型列表来自 `ListAgentPlanUsageDetailObjects` 的 `RespModelID`。

模型用量来自 `GetAgentPlanSeatUsageDetails`。解析器支持火山用量接口常见的：

- `UsageResults`
- `MetricItems`
- `Values[{ Timestamp, Value }]`
- `PromptTokens` / `InputTokens`
- `CompletionTokens` / `OutputTokens`
- 缓存命中 Token
- 请求次数

如果用量响应中的模型行没有重复返回模型名，解析器按同一次模型列表接口的顺序配对。

## 隐私与资源限制

- 不把 Cookie、Authorization、AccessKey 或 SecretKey写入应用状态。
- 不保存完整网络响应历史。
- 只保留三个请求模板，且仅存在于当前 WebView 会话。
- 主程序只接收 AFP、模型 Token、调用次数和诊断摘要。

## 与 DeepSeek 的差异

DeepSeek 可以直接从本地登录令牌调用平台接口。火山控制台接口还依赖 CSRF、`x-web-id` 和席位请求体，因此 v0.9.8 需要一次页面自举来建立模板。

完成自举后，两者的日常刷新方式相同：使用现有网页登录态主动调用接口，而不是依赖当前可见页面内容。火山会话失效时会自动返回自举流程。
